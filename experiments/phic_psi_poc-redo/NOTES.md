### ⚠ Correction (2026-09-16, same day) — the coa_phase "recovery" above does not hold up against the scatter plots; std_ratio alone is not a substitute for eyeballing predicted-vs-true

The claim in an earlier draft of this entry — that `lam010_retune_b`'s coa_phase clearing the gate was "a real recovery, not an artifact of the window" — does not survive a look at the training-time scatter plots already written to `runs/phic_psi_lam010_retune_b/20260915_181803/scatter/epoch_{0005,0080}.png` (per `_build_callbacks`' scatter-subset hook, no extra GPU work needed to view these). This is exactly the failure mode this repo's diagnostics are supposed to catch, caught one level too late — a good aggregate statistic (std_ratio≈0.93, "healthy") was taken at face value without checking the actual predicted-vs-true shape underneath it.

**What the scatter shows, at both epoch 5 and epoch 80 (same qualitative shape throughout — not something that emerged late):** `φc`'s "predicted (unwrapped) vs. true" panel is not a diagonal cloud — it is **two flat, horizontal bands** (≈−1.2 and ≈+5.2 rad, which are the same angle mod 2π), each covering roughly half the true-value range, with **no slope within either band**. The model is not predicting a per-sample phase at all; it is emitting a value close to one constant direction, and the branch-unwrapping logic (per `formulae_reference.md` A.8) is splitting that single constant into two apparent "bands" depending on which side of the true value it falls on. `val_std_ratio_coa_phase`'s climb from 0.62 (epoch 0) through a spike to 1.66 (epoch 10) down to 0.25 (epoch 20) and settling ≈0.90–0.93 from epoch 40 on is consistent with a **fixed, collapsed output whose population spread happens to converge near the true population's spread** — not with the model learning to track individual samples. This is a std_ratio false PASS: the gate's healthy-band criterion was calibrated to catch collapsed/underdispersed outputs, and it did not catch this one, because a bimodal-constant output can have "healthy" aggregate variance while carrying zero per-sample information.

**The reverse asymmetry also shows up, worth recording precisely because it cuts the other way:** `polarization_angle` (`ψ`) in the *same* run — which FAILS the gate (final std_ratio=0.421) — shows two-branch scatter clusters that each have a real positive slope tracking true `ψ` (visible at both epoch 5 and epoch 80, `.../scatter/epoch_0080.png`'s ψ panel), consistent with the pre-existing, already-documented 2-fold branch ambiguity in ψ reconstruction (`formulae_reference.md` A.8: "ψ is 2-fold ambiguous") rather than pure non-learning. `lam010_retune_a`'s (baseline-mode control) ψ panel shows the same two-branch-with-slope structure. This doesn't flip the mechanical Step 0 verdict — std_ratio<0.5 is still a FAIL by the pre-registered threshold, and that threshold is not renegotiated after seeing this — but it means "FAIL" here is not straightforwardly "no learning" either; the true picture is more mixed than either the PASS or the FAIL label alone conveys.

**This does not change the round's verdict.** The pre-registered rule (`preregistration_lam_retune.md`) is binary and mechanical by design specifically so a result like this — one metric looking better than it is, another looking worse than it is — doesn't get relitigated per-case after the fact. λ=0.10 still fails 3 of 4 readings by the letter of the criterion, and "λ alone insufficient, post-formula-fix" stands as the verdict of record. What this correction changes is confidence in what "healthy std_ratio" *means* on its own: it does not, by itself, certify that a head is producing a real per-sample regression — only a scatter plot does that. Recommending (not yet actioned) that any future Step 0-style gate add a mandatory scatter-plot check alongside the std_ratio number, rather than treating std_ratio as sufficient on its own — flagged in `experiment_index.md`'s "What's still open?" for follow-up.

### Two further findings from a second-opinion review (2026-09-18), one refining the collapse read, one a genuinely new methodology gap

An external review of this session's scatter-vs-p-value discipline raised several points; most were already handled by this investigation's existing wrap-aware `angular_mae`/period conventions (`polarization_angle`'s `period=π` vs. `coa_phase`/`inclination`'s `period=2π` — verified directly against `heads_spec.py`, already correct throughout every ported script) or amounted to renaming statistics already reported (`circular_r` *is* the mean resultant length R already headlined in `analyse_predictions.py`). Two points held up and are recorded here.

**(a) "COLLAPSE" was conflating two different failure modes — genuinely collapsed vs. genuinely bimodal.** `analyse_predictions.py`'s 3-way grade (`ok`/`~`/`XX`/`COLLAPSE`) doesn't distinguish a single-mode constant output from a real two-branch degenerate one, and the `periodic_heads.csv` peak data it already computed (but this investigation hadn't foregrounded) shows both patterns are present: `poc_b`'s `polarization_angle` has **one** peak carrying 99.9% of all 5,000 predictions — a true single-mode collapse, no information. `tcn`'s `polarization_angle` has **two** close-magnitude peaks (78°: 13.6%, 147°: 12.9%) — genuinely bimodal, consistent with the pre-existing, already-documented 2-fold `ψ` branch ambiguity (`formulae_reference.md` A.8), not a collapse to a single constant. `tcn`'s `coa_phase` shows the same two-peak pattern (65°: 12.1%, 335°: 8.1%). This doesn't change any verdict — both patterns still fail to track true values, and the formal bootstrap null covers both — but it sharpens what "fails" means per model: `poc_a`/`poc_b` are non-informative because they collapsed to (near-)one value; `tcn` is non-informative despite showing real bimodal structure, because that structure reflects a known ambiguity rather than per-sample recovery.

**(b) `inclination`'s encoding permits physically-invalid outputs, and roughly half the certified models actually produce them.** Checked `heads_spec.py` directly: `inclination` is declared `TransformKind.PERIODIC, period=2π` — the same full-circle sin/cos-then-`atan2` encoding as `coa_phase` — even though true `ι` is physically restricted to `[0, π]` (`sin(ι) ≥ 0` always; true labels never populate the lower half of the circle). The raw network output has no such constraint (`activation="linear"`, unclamped). Checked whether this matters empirically: `poc_a`'s and `tcn`'s predicted circular *mean* direction for `inclination` has `sin(mean) = −0.84` and `−0.93` respectively — both land in the physically-impossible half of the circle; `poc_b` (`sin=+0.19`) and `cnn_attention` (`sin=+0.82`) land in the valid half. This is a genuine, previously-unflagged model-behavior finding, not a statistical bug: the empirical bootstrap null (computed by shuffling the actual predicted values, whatever range they occupy) stays valid regardless of which half predictions land in, so it doesn't revise the "small-but-real, sub-floor" `inclination` verdict above. It is, however, a plausible partial explanation for why `inclination` recovery is as weak as it is (r≈0.35–0.60) — the network can waste output range on angles no true label ever takes, and two of four models' own mean prediction does exactly that. Worth a design note for any future campaign: bound `ι` to `[0,π]` directly (e.g. a scaled/shifted sigmoid) rather than an unconstrained full-circle encoding. Not actioned this session — no retraining implied or requested.

But it is the single most interesting open thread this redo has produced, and it's specifically flagged here rather than folded quietly into a closing summary: **`cnn_attention`'s sky-localization result needs an SNR-stratification check (or an equivalent per-sample-recovery test) before it can be called real skill instead of a memorization-driven population bias.**

**Follow-up check (2026-09-18, same day): the simplest population-bias explanation is now ruled out, not just suspected.** Computed directly from the true validation labels (5,000 samples, CPU-only, no model): `sin(dec)` has mean=0.0069, std=0.574 (uniform-on-sphere theory: mean=0, std=0.577) — the true sky-position population is genuinely uniform, no detectable clustering. A hypothetical model that always predicts the single population-mean direction, ignoring the input entirely, scores **89.41° mean separation — statistically indistinguishable from the 90° null**, nowhere near `cnn_attention`'s 77.52°. So the laziest possible shortcut (ignore the input, guess the population average) cannot explain this result; whatever `cnn_attention` is doing uses something sample-specific, not a population skew.

This leaves two live, non-exclusive explanations rather than one dismissible one: **(a)** genuine, if partial, localization via cross-detector amplitude ratio — this dataset has only 2 detectors (H1/L1), so full timing-triangulation is essentially unavailable (consistent with everyone's ~90° null baseline), but sky position also drives each detector's antenna-pattern response (`curriculum.py`/`formulae_reference.md` A.5 already model `F_plus`/`F_cross` as explicit functions of sky position for this exact reason), so the *relative* H1/L1 amplitude carries some real, coarse directional information independent of timing — plausible that an attention architecture extracts this better than a TCN; **(b)** a subtler shortcut than pure population-mean collapse, consistent with this model's already-documented memorization tendency, not ruled out by the centroid test above. **SNR-stratification remains the decisive discriminator**, same logic used throughout this investigation: real physical recovery (path a) should improve monotonically with SNR; a memorization-style shortcut (path b) has no reason to track signal quality. Not run yet.

`cnn_attention` passes both conditions of the Step-3-style test: monotonic improvement across all three SNR terciles, and the high-SNR tercile alone clears the 5.73° (0.10 rad) floor by nearly 3× — actually a *larger* effect (+15.53°) than the pooled bootstrap result (+12.58°), since the low/mid terciles pull the average down. `poc_a`/`poc_b`/`tcn` all read cleanly NULL — flat, non-monotonic, sub-floor — no change from the earlier picture.

**This meaningfully weakens the memorization-shortcut hypothesis without claiming certainty about mechanism.** A training-set-memorization artifact has no reason to track per-sample SNR; a genuine strain→direction mapping does, and that's the pattern observed. "REAL-RECOVERY-CONSISTENT" is the honest label this investigation's own decision-table language uses — not "proven" — since the specific physical channel (cross-detector H1/L1 amplitude-ratio information via sky-dependent antenna pattern, the leading hypothesis above) was never directly tested, only found consistent with the SNR-dependence observed here.

**Closes this thread.** Peripheral to the redo's central `coa_phase`/`polarization_angle` question, which stands unaffected — but this is the first result anywhere in this investigation, original or redo, to pass every check this repo's own discipline requires of a positive finding: statistically significant, floor-clearing, and monotonic with SNR. Worth carrying forward as a genuine, if secondary, discovery of this redo rather than filed away as noise.

### Stratification checks (inclination, inclination-control, SNR): consistent with the null, no floor-clearing effect anywhere

All three checks are consistent with each other and with `bootstrap_ang_mae.py`'s formal null.
